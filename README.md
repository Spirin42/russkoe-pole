# Русское поле

Бесконечный фасад, составленный программно из фотографических фрагментов. Карта одинакова для всех: вид квартиры и исходный свет определяются ее координатами. В кадре нет крыши, земли и внешних границ здания.

## Ссылка

[spirin42.github.io/russkoe-pole](https://spirin42.github.io/russkoe-pole/) — страница открывается без установки. Это самостоятельная копия: свет сохраняется в браузере и виден только вам. Общее поле требует запущенного `server.py`, см. ниже.

## Открыть сразу

Откройте `index.html` в браузере. Все изображения, стили и код находятся внутри файла; интернет не нужен. Изменения света и положение камеры сохраняются в браузере. Если браузер запрещает сохранение для локальных файлов, страница сообщит об этом.

## Общее поле

Положите `server.py` и `index.html` в одну папку. Нужен Python 3.9 или новее, дополнительные библиотеки не требуются.

Из этой папки запустите:

```sh
python3 server.py
```

Откройте `http://127.0.0.1:8000` в нескольких окнах браузера. Вверху появится «Общее поле». Ни в автономном файле, ни на странице GitHub Pages подписи о локальном режиме нет: без ответа от `/api/meta` подпись остаётся скрытой. Свет передается между посетителями в реальном времени, а изменения сохраняются в `field.sqlite3`. Сервер можно остановить и запустить заново — состояния останутся.

Чтобы открыть поле с телефона или другого компьютера в той же сети:

```sh
python3 server.py --host 0.0.0.0 --port 8000
```

На телефоне откройте в браузере адрес компьютера в локальной сети с портом `8000`, например `http://192.168.1.20:8000` (замените IP на адрес своего компьютера). На iPhone используйте браузер: предпросмотр HTML в приложении «Файлы» может не исполнять JavaScript.

Для зрителей из разных сетей этот же сервер нужно разместить на доступном им хосте. Страница на GitHub Pages — статическая копия без общего поля: размещение `server.py` в интернете не выполнено. При работе через обратный прокси для `/api/events` необходимо отключить буферизацию ответа; соединение использует Server-Sent Events. HTML и API должны открываться с одного домена. SQLite следует хранить на постоянном диске.

Самостоятельные копии HTML без общего сервера не обмениваются изменениями между устройствами. В них работает локальное сохранение. Локальные изменения не загружаются в общую карту автоматически. Если соединение с уже подключенным сервером пропало, нажатия сохраняются в очередь и повторяются после восстановления связи.

## Управление

| Действие | Компьютер | Телефон |
|---|---|---|
| Перемещение | Потянуть мышью или удерживать стрелки | Потянуть одним пальцем |
| Свет | Клик по квартире; Enter или пробел для квартиры в центре | Короткое касание |
| Масштаб | Колесо, клавиши + / − | Жест двумя пальцами |
| Начало | Клавиша Home | — |
| Подсказки | Нажмите на название «Русское поле» | Коснитесь названия «Русское поле» |

Свет переключается сразу, без анимации затухания или разгорания, включая изменения от других посетителей. Инерционный бросок после отпускания не обгоняет подготовленные квартиры: если впереди они еще не готовы, бросок замедляется до допустимой скорости. Перетаскивание пальцем или мышью не ограничено. Перетаскивание и изменение масштаба не переключают свет. Нажатие на глухую панель ничего не меняет и не показывает сообщений. Поддерживается системная настройка уменьшения движения.

Пока фасад готовится, по центру экрана крупно, как заставка, видно название «Русское поле». Когда видимая область и кольцо квартир вокруг нее нарисованы, название плавно гаснет, фасад проявляется, а название появляется на своем месте в левом верхнем углу. Подсказки внизу экрана нет.

Минимальный масштаб — 18%, начальный вид — 19%. Верхнее ограничение приближения временно снято: детали можно рассматривать колесом, клавишей + или жестом двумя пальцами. Положение камеры и выбранный масштаб сохраняются; значения ниже 18% приводятся к этой границе. Клавиша Home возвращает к началу с масштабом 19%. Нижняя панель кнопок удалена.

## Как устроено

- Псевдослучайные признаки вычисляются из координат. Свет, материал, фактуры, окна, балконы, кондиционеры, гирлянды и цвет освещения выбираются детерминированно.
- Каталог содержит 85 фотографических окон и 42 балкона (раньше 57 и 19). Из них программно собираются 413 различных конфигураций окон и 206 вариантов балконов: одностворчатые, двухстворчатые и трёхстворчатые окна, фрамуги, открытые створки, шторы, жалюзи, растения, разные виды остекления и четыре дополнительные фактуры ограждений. Это число композиций, а не число новых фотографий. Характерные детали исходных снимков иногда повторяются.
- При изменении числа створок вместе с фотографическими фрагментами преобразуются маски стекол; подоконник и верхний откос остаются цельными. Замена облицовки балкона сохраняет его рамы, перила, плиту и боковую грань. Новые варианты определяются координатами, как и остальная карта.
- Освещенные окна ярче бетонного фона; вокруг них есть мягкий ореол. Для каждого оконного фотослоя вручную размечено каждое стекло, включая балконные фрамуги и наклонные створки. Свет меняет только эти области, сохраняя цвет рам, перемычек и подоконников. Кондиционеры вырезаются по контуру из фотографии вечерней панельки, без чужого прямоугольного фона и рисованных трубок.
- Окна соединяются со стеной фотографическими откосами, сколами штукатурки и подоконниками. Фрагменты с обрезанными рамами и частями соседнего оборудования исключены. У балконов есть узкая боковая грань из той же облицовки, нижняя поверхность плиты, контактные и падающие тени. У открытого балкона выступает ограждение, а заднее окно остается в плоскости стены; посторонняя стена вокруг него удаляется мягкой маской. Балкон вписывается целиком с сохранением пропорций, без обрезки боковых створок.
- Швы имеют неровную кромку, переменную ширину, углубление, фактуру раствора, мелкие трещины и местные участки ремонта. Геометрия общего стыка вычисляется одинаково для обеих соседних ячеек. Фактура шва передискретизируется один раз для уровня детализации и накладывается на каждый шов пиксель в пиксель, а холсты швов переиспользуются. За основу взяты фотографии настоящих межпанельных швов, ссылка приведена ниже.
- Общая цветовая обработка, мелкое монохромное зерно и непрерывная фактура выветривания входят в изображение каждой квартиры и привязаны к координатам стены: при перемещении они движутся вместе с фасадом, а не лежат поверх экрана. Цвет фотослоев приглушен; яркие участки обработаны с плавным сжатием светов, чтобы сохранить детали. Пятна и зерно не обрываются на границах квартир. Зерно без мерцания; на каждом уровне детализации его размер около 0,72 CSS-пикселя. Во время плавного зума зерно масштабируется вместе с изображением, пока не будет готов следующий уровень детализации. Радиальная виньетка заметно затемняет края и углы экрана, сохраняя прозрачный центр; максимальная непрозрачность в углах — 72%.
- Фасад собирается из тайлов — отдельных canvas по нескольку квартир, которые браузер компонует на видеокарте. Перемещение и плавный зум внутри уровня детализации только сдвигают и масштабируют слой тайлов CSS-трансформацией: экран не перерисовывается в каждом кадре. На экране всегда только полностью нарисованные квартиры, упрощенных и временных изображений нет. Вокруг кадра заранее готовится запас квартир, больше в направлении движения; квартира, которая к моменту появления в кадре не успела подготовиться, рисуется до показа этого кадра. Квартира рисуется один раз — когда впервые понадобилась или когда меняется ее свет; переключение света перерисовывает только эту квартиру, в том же кадре. Явные уведомления об изменениях позволяют не опрашивать состояние всех окон в каждом кадре. Работа кадра делится на две фазы: сначала все чтения пикселей (перекраска стекол, варианты окон и балконов), потом рисование — чтение пикселей ждет всю отрисовку, поставленную в очередь до него, и в Safari и Chrome с GPU она идет в другом процессе. Доля кадра на подготовку запаса подстраивается под фактическую длительность кадров и частоту обновления экрана. Инерционный бросок ограничен уже подготовленными квартирами, поэтому никогда не вызывает дорисовку до показа кадра. Небольшое отдаление не меняет уровень детализации: текущий слой уменьшается компоновщиком до 0,7 своего разрешения, поэтому в планируемом рабочем диапазоне 18–20% квартиры не перерисовываются заново при каждом движении масштаба. При приближении прежний слой остается на экране, пока новый уровень не будет готов целиком; промежуточные уровни не рисуются, прежний слой увеличивается не более чем вдвое. При отдалении за пределы удержания прежний уровень остается поверх нового, сразу рисуются только квартиры, которых он не показывает, а когда новый уровень готов целиком, прежний убирается. Крупные квартиры еще не показанного уровня готовятся полосами за несколько кадров. В покое постоянного цикла работы нет. Разрешение подбирается по масштабу и плотности пикселей экрана; поддерживается Retina до 3× и до 1024 × 896 пикселей на квартиру. Это разрешение отрисовки геометрии и теней: фотографическая детализация ограничена исходными снимками и не растет бесконечно вместе с зумом.
- Готовые тайлы хранятся в кэше до 112 МиБ на устройствах с сенсорным указателем и до 256 МиБ на остальных, поэтому к недавно просмотренным местам можно вернуться без повторной отрисовки; тайлы на экране из кэша не вытесняются. Дополнительно ограничены кэши фотокомпозиций (24 МиБ), освещения (32 МиБ), межпанельных швов (8 МиБ) и обработанных материалов стены (12 МиБ). На дальнем плане свет рассчитывается по уменьшенным фотослоям, при приближении используются полные исходные детали. Для больших экранов разрешение адаптируется к числу видимых квартир. Готовый вариант света находится по устойчивому идентификатору, даже если промежуточная фотокомпозиция уже была вытеснена из кэша. Холсты для обработки пикселей используют режим willReadFrequently, а вывод остается отдельным. Пиксели каждой фотографии читаются для перекраски стекол один раз, дальше все варианты света строятся из этой копии.
- На дальнем плане клиент хранит только измененные состояния квартир. Загрузка большой области не создает записи для каждой нетронутой ячейки.
- Общая карта хранит только затронутые квартиры. Сервер атомарно переключает свет; уникальные идентификаторы запросов предотвращают повторное переключение при повторной отправке.
- Сервер отправляет посетителю изменения в его текущей области. Пропущенные события восстанавливаются при подключении, снимки состояния защищены номерами версий.
- Поле практически неограниченно: поддерживаются координаты от −2 миллиардов до +2 миллиардов по каждой оси.

## Исходники

- `renderer.js` — генерация фасада, фототекстуры, освещение, кэш и компоновка тайлов на странице.
- `app.js` — камера, управление, локальное сохранение и синхронизация.
- `style.css`, `template.html` — интерфейс.
- `assets/` — встроенные в итоговый HTML фотографии.
- `server.py` — HTTP, SQLite и поток событий без сторонних зависимостей.
- `build.py` — пересборка автономного файла командой `python3 build.py`.
- `index.html` — собранный автономный файл; его же раздаёт GitHub Pages.

## Проверка

Проверены отрисовка и управление в Chrome, изменение света между двумя открытыми страницами, передача событий независимому HTTP-клиенту, 101 одновременное переключение, повтор запроса, сохранение SQLite и совпадение генерации координат в Python и JavaScript. Касание, перетаскивание, жест двумя пальцами, клавиатура и восстановление локального состояния проверяются отдельным сценарием событий; физическое мобильное устройство в проверке не использовалось.

В текущем обновлении выполнены 635 проверок сочетаний исходных фотослоев и преобразований: пиксели за пределами масок стекол одинаковы при включенном и выключенном свете; найдено 619 различных композиций. Проверено совпадение сохраненного буфера с полной отрисовкой после перемещения, смены света, возвращения к ранее скрытой квартире, перехода к отрицательным координатам и изменения масштаба вплоть до 2400%. Отдельно проверены мгновенное переключение, управление мышью и сенсорными событиями, восстановление камеры и локального света. Физическое мобильное устройство в этой проверке не использовалось.

В обновлении от 19 сентября 2026 года отдельно проверены 42 ячейки при трех уровнях разрешения и обоих состояниях света: их пиксели полностью совпали с предыдущей версией. Проверены повторное использование света после вытеснения фотокомпозиции из кэша, точность кэша при зуме, переключении света и движении, молчаливое нажатие на глухую панель. Каталог деталей, фотографии и разрешения ячеек сохранены.

Сравнение с предыдущим HTML в одном сеансе Chrome: холст 1200 × 760, по 18 кадров в каждом сценарии, одинаковый маршрут. Значения — время вызова функции отрисовки, а не FPS; браузер тестового окружения ограничивает частоту кадров.

| Сценарий | До, среднее | После, среднее |
|---|---:|---:|
| Движение при масштабе 19%, включая вход в новую область | 25,7 мс | 25,1 мс |
| Плавный зум от 20% до 24,25% | 83,8 мс | 0,2 мс |
| Зум с переходами между уровнями детализации, от 25% до 92,5% | 481 мс | 394 мс |
| Первая отрисовка после подготовки фототекстур | 5,31 с | 4,32 с |

Медиана кадра при движении уменьшилась с 0,9 до 0,2 мс. Основное улучшение — плавный зум внутри уже готового уровня детализации. Построение полностью нового уровня или незнакомой области по-прежнему может дать задержку: в этом окружении максимум при смене уровня составил 2,93 с против 3,14 с. Абсолютные значения зависят от нагрузки тестового окружения и устройства; их нельзя сравнивать напрямую с замерами предыдущего дня.

В обновлениях от 24–25 сентября 2026 года зерно, фактура выветривания и общая цветовая обработка перенесены с экрана в изображение квартир, покадровая перерисовка экрана заменена компоновкой тайлов, на экран выводятся только полностью нарисованные квартиры, а недостижимый режим дальнего плана меньше 10% удален: минимальный масштаб — 18%. Проверки выполнены на Apple M1 в Chrome 150 и в WebKit 17.4 — движке Safari в сборке Playwright; Safari на iPhone и физический телефон не использовались.

- Пиксели: 240 квартир на трех уровнях детализации в обоих состояниях света сравнены с прежней отрисовкой при нейтральных зерне и фактуре. В Chrome среднее отличие — от 0,0001 до 0,02 уровня из 255; у одной квартиры 314 пикселей на кромке нижней плоскости балкона отличаются до 12 уровней, потому что клип квартиры пересекается с клипом самой плоскости. В WebKit среднее отличие — 0,07–0,08 уровня, отдельные пиксели до 11. Фактура шва, наложенная пиксель в пиксель, повторное использование холстов швов и перекраска стекол из сохраненной копии пикселей результат практически не меняют: в Chrome среднее отличие выросло на 0,005 уровня, максимум прежний.
- Зерно: после сдвига поля на 156 пикселей изображение совпадает со сдвинутым прежним кадром до пикселя, в том числе при дробном масштабе. У прежней версии в том же тесте отличались 28% значений: зерно оставалось на месте.
- Цельность: после каждого кадра проверялось, что все квартиры кадра нарисованы полностью. Во всех прогонах, включая глубокий зум, нарушений нет.
- На границах тайлов нет щелей: при плотности пикселей 1,25×, 1,5× и 2,2× на масштабах 19% и 27%, при 3× — от 19% до 57%. Проверено по контрастному фону под тайлами.
- Свет переключается в том же кадре, в том числе между двумя окнами общего поля. После 25 перемещений и трех циклов зума память тайлов и кэшей остается в пределах бюджетов, а число canvas на странице не растет. Доля кадра под подготовку восстанавливается после имитации смены частоты обновления 120 → 60 → 30 Гц.
- Стартовая надпись (Chrome и WebKit): пока фасад готовится, видна только надпись в центре; после готовности она гаснет, фасад проявляется, а заголовок появляется в углу с небольшой задержкой. При системной настройке уменьшения движения смена мгновенная.

Сравнение с прежним HTML: одинаковый сценарий из перемещений, бросков с инерцией и зума в диапазоне 18–20%; медианы трех прогонов (двух в профиле «Chrome, CPU ×4»), у самых долгих кадров — разброс между прогонами. «Телефон» — окно 390 × 844 при плотности 3×, «десктоп» — 1440 × 900 при плотности 2×. WebKit ближе всего к Safari на iPhone и Mac. Профиль «CPU ×4» — Chrome с отключенным ускорением canvas и процессором, замедленным в 4 раза. Частота кадров тестовых браузеров ограничена 60. Квартиры, которые не успели подготовиться заранее, рисуются до показа кадра, поэтому быстрые перетаскивания на больших экранах при отрисовке canvas процессором по-прежнему дают просадки: в WebKit на десктопе так дорисовывалось около 700 квартир за сценарий перемещений, кадров длиннее 50 мс было 20 против 133 в прежней версии. На телефоне в WebKit таких квартир было 32 за сценарий, кадров длиннее 50 мс не было. Инерционный бросок подготовку не обгоняет: в серии быстрых бросков синхронно дорисованных на инерции квартир ноль, без ограничения их было 183 на десктопе и 390 на телефоне; в тех же бросках на телефоне поле прошло 76 рядов вместо 130.

В профиле «Chrome, CPU ×4» фасад появляется позже прежнего (3,9 → 5,2 с на телефоне, 7,4 → 8,7 с на десктопе): теперь до показа рисуется еще и кольцо вокруг видимой области, а работа делится на порции между кадрами.

Планируемый рабочий диапазон масштаба — 18–20%. Отдаление с 19% до 18,5% на экране 1440 × 900 при плотности 2× перерисовывает 33 новые квартиры на краях кадра; без удержания уровня детализации перерисовывались бы все 858 квартир кадра.

В WebKit стоимость квартиры определяется числом операций рисования, а не числом пикселей: при масштабах 0,5 и 0,75 она одинакова. До оптимизаций швы занимали около 80% растеризации квартиры; наложение фактуры шва пиксель в пиксель и повторное использование холстов снизили стоимость квартиры в WebKit с 5,3 до 2,4 мс. Вместе с копией пикселей каждой фотографии для перекраски стекол это сократило и подготовку квартиры перед рисованием — с 3,2 до 1,7 мс: чтения пикселей меньше ждут очереди отрисовки.

Глубокий зум до 270% доступен, пока снято верхнее ограничение масштаба. WebKit, телефон: приближение с дорисовкой — 57 кадров/с, самый долгий кадр 38 мс (было 38 кадров/с и 771 мс); перемещение на этом масштабе — 60 кадров/с; возврат к 19% — 55 кадров/с, самый долгий кадр 106 мс (было 33 кадра/с и 1043 мс). При отдалении прежний уровень остается поверх нового, а сразу рисуются только квартиры, которых он не показывает.
